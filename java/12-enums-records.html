Enums, records and sealed types

Three ways to say precisely what your data is — and let the compiler enforce it.

Enums: a fixed set of values

public enum Status {
    PENDING, ACTIVE, SUSPENDED, CLOSED
}

Status s = Status.ACTIVE;
if (s == Status.ACTIVE) { ... }        // == is correct and safe for enums

Compare with the alternative — a String status, where "activ" compiles fine and fails in production. An enum makes invalid values impossible.

Built-in members

Status.values()                 // [PENDING, ACTIVE, SUSPENDED, CLOSED]
Status.valueOf("ACTIVE")        // ACTIVE — throws IllegalArgumentException if unknown
Status.ACTIVE.name()            // "ACTIVE"
Status.ACTIVE.ordinal()         // 1 — position; never persist this, order can change

for (Status st : Status.values()) System.out.println(st);

Enums with state and behaviour

public enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    EARTH  (5.976e+24, 6.37814e6);

    private final double mass;
    private final double radius;

    Planet(double mass, double radius) {   // constructor is implicitly private
        this.mass = mass;
        this.radius = radius;
    }

    public double surfaceGravity() {
        return 6.67300E-11 * mass / (radius * radius);
    }
}

Planet.EARTH.surfaceGravity();   // 9.8...

Per-constant behaviour

public enum Operation {
    PLUS("+")  { public int apply(int a, int b) { return a + b; } },
    MINUS("-") { public int apply(int a, int b) { return a - b; } };

    private final String symbol;
    Operation(String symbol) { this.symbol = symbol; }

    public abstract int apply(int a, int b);
    public String symbol() { return symbol; }
}

Operation.PLUS.apply(2, 3);   // 5

Enums in switch

String message = switch (status) {
    case PENDING   -> "Waiting for approval";
    case ACTIVE    -> "All good";
    case SUSPENDED -> "Contact support";
    case CLOSED    -> "Account closed";
};    // no default needed: the compiler knows the set is complete

That exhaustiveness check is the killer feature: add a constant later and every switch that does not handle it stops compiling, so you cannot forget one.

EnumMap and EnumSet

Map<Status, Integer> counts = new EnumMap<>(Status.class);   // array-backed, very fast
Set<Status> open = EnumSet.of(Status.PENDING, Status.ACTIVE);
Set<Status> all = EnumSet.allOf(Status.class);

Records: transparent, immutable data

Java 16+. A record declares "this type is just these values":

public record Point(int x, int y) { }

That one line generates: private final fields, a canonical constructor, accessors x() and y(), plus equals, hashCode and toString.

Point p = new Point(3, 4);
p.x();                          // 3   (note: x(), not getX())
p.toString();                   // Point[x=3, y=4]
new Point(3, 4).equals(p);      // true — value equality for free

The equivalent class is about 40 lines, and every one of them is a chance to get equals wrong.

Validation and extra members

public record Money(String currency, BigDecimal amount) {

    public Money {                                  // compact constructor
        Objects.requireNonNull(currency, "currency");
        if (amount.signum() < 0) throw new IllegalArgumentException("amount must be >= 0");
    }

    public Money plus(Money other) {                // extra methods are fine
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
        return new Money(currency, amount.add(other.amount));
    }

    public static Money euros(String amount) {      // static factory
        return new Money("EUR", new BigDecimal(amount));
    }
}

What records cannot do

  • No additional instance fields beyond the components.
  • Always final — no extends (they can implement interfaces).
  • Components are final; "changing" one means constructing a new record.

When to use one

DTOs crossing a boundary, API request and response bodies, value objects (money, coordinates, ranges), keys in maps, and returning more than one value from a method:

record SplitResult(List<String> valid, List<String> invalid) { }

SplitResult result = validateAll(input);
result.valid().forEach(System.out::println);

Use a normal class when the object has mutable state or identity (a JPA entity, a service, anything with a lifecycle).

Sealed types: a closed hierarchy

Java 17+. Sealing says exactly which types may extend or implement yours:

public sealed interface Shape permits Circle, Rectangle, Triangle { }

public record Circle(double radius)               implements Shape { }
public record Rectangle(double w, double h)       implements Shape { }
public record Triangle(double base, double height) implements Shape { }

Combined with pattern matching, the compiler again checks that you handled every case:

double area(Shape shape) {
    return switch (shape) {
        case Circle c    -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.w() * r.h();
        case Triangle t  -> t.base() * t.height() / 2;
    };                                     // exhaustive: no default required
}

A permitted subclass must itself be final, sealed, or explicitly non-sealed.

Record patterns

String describe(Shape shape) {
    return switch (shape) {
        case Circle(double r) when r > 10 -> "big circle";
        case Circle(double r)             -> "circle of radius " + r;
        case Rectangle(double w, double h) when w == h -> "square";
        case Rectangle r                  -> "rectangle";
        case Triangle t                   -> "triangle";
    };
}

This is how you model "one of these alternatives" — the equivalent of a sum type in other languages — and it is increasingly common in modern Java.

Choosing between them

UseWhen
enumA value is one of a fixed, known set: statuses, roles, currencies, day of week.
recordAn immutable bundle of values with no identity: DTOs, coordinates, results.
sealed interface + recordsA value is one of several shapes, each with its own data: events, commands, results that succeed or fail.
classMutable state, identity, lifecycle, framework-managed objects.
