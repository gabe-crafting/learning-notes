Operators and expressions

Short lesson, high value: the symbols you will read thousands of times, plus the handful whose behaviour surprises people.

Arithmetic

int a = 17, b = 5;
a + b   // 22
a - b   // 12
a * b   // 85
a / b   // 3   integer division: the remainder is discarded
a % b   // 2   modulo: the remainder

% is more useful than it looks: n % 2 == 0 tests even, i % list.size() wraps an index around, seconds % 60 splits a duration.

Note that % keeps the sign of the left operand: -7 % 3 is -1, not 2. If you need a non-negative result, use Math.floorMod(-7, 3).

Assignment and compound assignment

int x = 10;
x += 5;    // x = x + 5  → 15
x -= 3;    // 12
x *= 2;    // 24
x /= 4;    // 6
x %= 4;    // 2

Compound assignment hides a cast: byte b = 10; b += 300; compiles (and overflows) where b = b + 300; would not.

Increment and decrement

int i = 5;
int p = i++;   // p = 5, i = 6   (post: use, then increment)
int q = ++i;   // q = 7, i = 7   (pre: increment, then use)

In a loop header the difference is irrelevant. Anywhere else, prefer a separate statement — clever one-liners built on i++ are a classic source of bugs.

Comparison

a == b    // equal          (identity for references!)
a != b    // not equal
a <  b    a <= b    a > b    a >= b
String s1 = "hello";
String s2 = "hel" + lo();          // built at runtime
s1 == s2         // false — different objects
s1.equals(s2)    // true  — same characters

Use == for primitives and for enum constants and null checks; use equals for everything else.

Logical operators

&&   and    (short-circuits: right side not evaluated if left is false)
||   or     (short-circuits: right side not evaluated if left is true)
!    not
^    exclusive or

Short-circuiting is not just an optimisation — it is how you guard:

if (user != null && user.isActive()) { ... }     // safe
if (user.isActive() && user != null) { ... }     // NullPointerException

The single-character forms & and | also work on booleans but always evaluate both sides. You will rarely want them.

Ternary conditional

String label = count == 1 ? "item" : "items";
int max = a > b ? a : b;

Good for a single small choice inside an expression. If you find yourself nesting ternaries, use an if.

Operator precedence

From tightest to loosest, the part worth memorising:

1++ -- ! (unary), casts
2* / %
3+ -
4< <= > >= instanceof
5== !=
6&& then ||
7? : then = += -= …
int r = 2 + 3 * 4;             // 14, not 20
boolean ok = a > 0 && b > 0 || c > 0;   // (a>0 && b>0) || c>0

When in doubt, add brackets. Nobody has ever been criticised in code review for brackets that made intent obvious.

String concatenation with +

String s = "Total: " + 3 + 4;      // "Total: 34"   — left to right!
String t = "Total: " + (3 + 4);    // "Total: 7"

Once one operand is a String, + means concatenation and everything to the right is converted to text.

Bitwise operators

Rare in business code, common in libraries, permissions and low-level work:

&    and          6 & 3  == 2      (0110 & 0011 = 0010)
|    or           6 | 3  == 7
^    xor          6 ^ 3  == 5
~    not          ~6     == -7
<<   shift left   1 << 4 == 16       (multiply by 2^4)
>>   shift right  16 >> 2 == 4        (sign-preserving)
>>>  unsigned shift right

instanceof and pattern matching

// classic
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// Java 16+: pattern matching binds the variable for you
if (obj instanceof String s && s.length() > 3) {
    System.out.println(s.toUpperCase());
}

Statements versus expressions

An expression produces a value (a + b, list.size(), x > 0 ? 1 : 0). A statement does something (int x = 5;, an if, a loop). Java is picky about which goes where, and the compiler error "not a statement" usually means you wrote an expression on its own line.

Practice
  1. Write isLeapYear(int year) using only %, && and ||: divisible by 4, except centuries, unless divisible by 400.
  2. Convert a total number of seconds into h:mm:ss using / and %.
  3. Predict, then check in jshell: 1 + 2 + "3" + 4 + 5.
  4. Explain why if (s != null && s.isEmpty()) is safe but swapping the operands is not.
  5. Write a check that a number is a power of two using a single bitwise expression.
