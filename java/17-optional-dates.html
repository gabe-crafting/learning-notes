Optional, dates and utilities

Handling absence properly, working with time correctly, and the standard-library helpers you should not reimplement.

Optional

Optional<T> is a container that either holds a value or is empty. Its job is to make "there may be nothing here" part of the type, so the caller cannot forget.

// before
public User findByEmail(String email) {
    return null;                       // callers forget to check → NullPointerException
}

// after
public Optional<User> findByEmail(String email) {
    return Optional.empty();           // the signature says it may be absent
}

Creating

Optional.of(value)              // value must not be null, else NPE
Optional.ofNullable(maybeNull)  // empty if null   ← the usual choice
Optional.empty()

Using it

Optional<User> found = repository.findByEmail(email);

// default value
User user = found.orElse(User.GUEST);
User user = found.orElseGet(() -> createGuest());     // lazy — only runs if empty

// or fail
User user = found.orElseThrow();                       // NoSuchElementException
User user = found.orElseThrow(() -> new UserNotFoundException(email));

// act if present
found.ifPresent(u -> log.info("Found {}", u.name()));
found.ifPresentOrElse(this::send, () -> log.warn("no user"));

// transform without unwrapping
String name = found.map(User::name).orElse("unknown");
Optional<String> city = found.flatMap(User::city);     // when the mapper returns Optional
Optional<User> active = found.filter(User::isActive);

// as a stream
found.stream().forEach(...);

Using it badly

if (found.isPresent()) {          // this is just a null check with extra steps
    User u = found.get();
}
found.get();                       // throws if empty — avoid outside tests

Guidelines that keep Optional useful:

  • Use it as a return type for "might not find anything".
  • Do not use it for fields or method parameters — it is not serialisable and it clutters constructors. Overload the method instead.
  • Never return null from a method that returns Optional. That is a special circle of confusion.
  • For collections, return an empty list rather than an Optional<List>.

Dates and times (java.time)

Java 8 replaced the broken Date/Calendar API. Everything in java.time is immutable and thread-safe. Never use java.util.Date or SimpleDateFormat in new code.

LocalDateA date with no time or zone — birthdays, invoice dates
LocalTimeA time with no date — opening hours
LocalDateTimeBoth, still no zone — usually not what you want for events
InstantA point on the UTC timeline — timestamps, "created at"
ZonedDateTimeDate, time and zone — meetings, anything user-facing
DurationA time-based amount (seconds, minutes)
PeriodA date-based amount (days, months, years)
LocalDate today = LocalDate.now();
LocalDate d = LocalDate.of(2026, 3, 14);
LocalDate parsed = LocalDate.parse("2026-03-14");        // ISO format by default

d.plusDays(10);  d.minusMonths(2);  d.plusYears(1);      // return NEW objects
d.getDayOfWeek();  d.getMonthValue();  d.lengthOfMonth();  d.isLeapYear();
d.isBefore(today);  d.isAfter(today);
d.withDayOfMonth(1);

Instant now = Instant.now();                              // store timestamps as UTC
ZonedDateTime local = now.atZone(ZoneId.of("Europe/Bucharest"));

Duration meeting = Duration.ofMinutes(90);
Duration between = Duration.between(start, end);
between.toMinutes();

Period age = Period.between(birthday, today);
age.getYears();

long days = ChronoUnit.DAYS.between(start, end);

Formatting and parsing

DateTimeFormatter fmt = DateTimeFormatter.ofPattern("dd/MM/yyyy");
String text = date.format(fmt);                  // "14/03/2026"
LocalDate back = LocalDate.parse("14/03/2026", fmt);

date.format(DateTimeFormatter.ISO_DATE);         // 2026-03-14
dateTime.format(DateTimeFormatter.ofLocalizedDateTime(FormatStyle.MEDIUM));
Rules that save you pain Store instants in UTC; convert to a zone only when displaying. Never store a zone offset as a substitute for a zone id (offsets change twice a year). For "a date the user picked", LocalDate is correct — do not attach a time to it.

Math and random

Math.abs(-5)        Math.max(a, b)      Math.min(a, b)

Math.floor(2.9)     Math.ceil(2.1)      Math.floorMod(-7, 3)
Math.random()                            // 0.0 <= x < 1.0

random.nextInt(1, 7);       // 1..6  (Java 17+)
random.nextDouble();
random.nextBoolean();

ThreadLocalRandom.current().nextInt(1, 7);   // better in multithreaded code
new Random(42);                               // fixed seed → reproducible, useful in tests

Objects

Objects.equals(a, b)                    // null-safe equality
Objects.hash(field1, field2)            // for hashCode
Objects.requireNonNull(arg, "arg")      // fail fast with a clear message
Objects.requireNonNullElse(value, "default")
Objects.toString(maybeNull, "n/a")
Objects.isNull(x)   Objects.nonNull(x)  // handy as method references in streams

BigDecimal for money

BigDecimal price = new BigDecimal("19.99");     // from a String, never a double
BigDecimal qty = BigDecimal.valueOf(3);

BigDecimal total = price.multiply(qty);          // immutable: use the result
total = total.setScale(2, RoundingMode.HALF_UP);
total.compareTo(BigDecimal.ZERO) > 0;            // compare with compareTo, not equals
// equals also compares scale: 1.0 is NOT equal to 1.00

Regex utilities

Pattern EMAIL = Pattern.compile("^[\\w.+-]+@[\\w-]+\\.[\\w.]+$");   // compile once, reuse
EMAIL.matcher(input).matches();

Matcher m = Pattern.compile("(\\d{4})-(\\d{2})").matcher(text);
while (m.find()) {
    System.out.println(m.group(1) + " / " + m.group(2));
}

Practice
  1. Change a findById method that returns null into one returning Optional, then update every caller.
  2. Write ageInYears(LocalDate birthday) and workingDaysBetween(LocalDate, LocalDate).
  3. Print the current time in three time zones from a single Instant.
  4. Compute an order total with BigDecimal, rounded to two decimals, and show why double gets it wrong.
  5. Chain map, filter and orElseThrow on an Optional without ever calling isPresent.
