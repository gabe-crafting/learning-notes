Collections framework

The data structures you will reach for every single day. Knowing which to pick, and why, is a junior-level expectation in every interview and code review.

The map of the framework

Iterable
└── Collection
    ├── List      ordered, duplicates allowed, indexed
    │   ├── ArrayList      ← default
    │   └── LinkedList
    ├── Set       no duplicates
    │   ├── HashSet        ← default
    │   ├── LinkedHashSet  insertion order
    │   └── TreeSet        sorted
    └── Queue / Deque
        ├── ArrayDeque     ← default stack/queue
        └── PriorityQueue  sorted by priority

Map  (not a Collection)
├── HashMap        ← default
├── LinkedHashMap  insertion order
└── TreeMap        sorted by key

List

List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Linus");
names.add(0, "Grace");        // insert at index

names.get(0);                 // "Grace"
names.set(1, "Ada L.");       // replace
names.remove("Linus");        // by value
names.remove(0);              // by index — careful with List<Integer>!
names.size();
names.contains("Ada");
names.indexOf("Ada");
names.isEmpty();
names.clear();

for (String n : names) { ... }
names.forEach(System.out::println);

Immutable lists

List<String> fixed = List.of("a", "b", "c");     // Java 9+, immutable, rejects null
fixed.add("d");                                   // UnsupportedOperationException

List<String> mutable = new ArrayList<>(fixed);   // a modifiable copy
List<String> view = Collections.unmodifiableList(mutable);  // read-only view

Returning List.of(...) or a copy from a getter is how you stop callers mutating your internals.

ArrayList versus LinkedList

OperationArrayListLinkedList
get(i)O(1)O(n)
add at the endamortised O(1)O(1)
insert/remove in the middleO(n)O(1) once you are there
Memorycompact arraynode objects and pointers

Use ArrayList. In practice its cache locality beats LinkedList even in cases the table suggests otherwise; the only common exception is a queue, and ArrayDeque is better there anyway.

Set

Set<String> tags = new HashSet<>();
tags.add("java");
tags.add("java");            // ignored — returns false
tags.contains("java");       // O(1)
tags.remove("java");
HashSetNo order guaranteed. Fastest. Needs correct hashCode/equals.
LinkedHashSetKeeps insertion order, small overhead.
TreeSetSorted; elements must be Comparable or you supply a Comparator. O(log n).
// deduplicate while keeping order
List<String> unique = new ArrayList<>(new LinkedHashSet<>(withDuplicates));

// set algebra
a.retainAll(b);   // intersection
a.addAll(b);      // union
a.removeAll(b);   // difference

Map

Map<String, Integer> stock = new HashMap<>();
stock.put("apple", 5);
stock.put("apple", 8);              // replaces; returns the old value

stock.get("apple");                 // 8    — null if absent
stock.getOrDefault("pear", 0);      // 0    — safer
stock.containsKey("apple");
stock.remove("apple");
stock.size();

stock.putIfAbsent("pear", 1);
stock.computeIfAbsent("pear", k -> expensiveLookup(k));
stock.merge("apple", 1, Integer::sum);      // add 1, or start at 1 — the counting idiom

for (Map.Entry<String, Integer> e : stock.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
stock.forEach((k, v) -> System.out.println(k + " = " + v));
stock.keySet();  stock.values();  stock.entrySet();

Counting, the idiomatic way

Map<String, Integer> counts = new HashMap<>();
for (String word : words) {
    counts.merge(word, 1, Integer::sum);
}

Map<String, List<Order>> byCustomer = new HashMap<>();
for (Order o : orders) {
    byCustomer.computeIfAbsent(o.customerId(), k -> new ArrayList<>()).add(o);
}

hashCode and equals — why they matter here

class Point {
    int x, y;
    // no equals/hashCode overridden!
}

Set<Point> set = new HashSet<>();
set.add(new Point(1, 1));
set.add(new Point(1, 1));
set.size();                       // 2 — they are not "equal" without an equals method

Hash-based collections find an element by its hash bucket first, then by equals. Rules:

  • Equal objects must return equal hash codes.
  • hashCode must be stable — never build it from mutable fields you then change while the object sits in a set or map key.
  • Records give you both, correctly, for free.

Deque: stack and queue

Deque<String> stack = new ArrayDeque<>();
stack.push("a"); stack.push("b");
stack.pop();      // "b"  — LIFO
stack.peek();     // "a"  — look without removing

Deque<String> queue = new ArrayDeque<>();
queue.offer("first"); queue.offer("second");
queue.poll();     // "first" — FIFO

PriorityQueue<Task> tasks = new PriorityQueue<>(Comparator.comparingInt(Task::priority));

The old java.util.Stack and Vector are synchronised legacy classes — do not use them in new code.

Iterating and modifying

// ConcurrentModificationException
for (String name : names) {
    if (name.isBlank()) names.remove(name);       // boom
}

// correct: Iterator
Iterator<String> it = names.iterator();
while (it.hasNext()) {
    if (it.next().isBlank()) it.remove();
}

// simplest: removeIf
names.removeIf(String::isBlank);

Sorting

names.sort(Comparator.naturalOrder());
names.sort(Comparator.reverseOrder());
people.sort(Comparator.comparing(Person::lastName)
                      .thenComparing(Person::firstName));
people.sort(Comparator.comparingInt(Person::age).reversed());
Collections.sort(names);          // older equivalent
Collections.shuffle(names);
Collections.max(numbers);         Collections.min(numbers);

Choosing a collection

You need…Use
An ordered list you index intoArrayList
Uniqueness, order irrelevantHashSet
Uniqueness, keep insertion orderLinkedHashSet
Always-sorted elementsTreeSet
Key → value lookupHashMap
Key → value, sorted keys or range queriesTreeMap
Stack or queueArrayDeque
Highest-priority item firstPriorityQueue
Shared across threadsConcurrentHashMap, CopyOnWriteArrayList

Practice
  1. Count word frequency in a paragraph with a HashMap, then print the top five by count.
  2. Given two lists, produce their intersection, union and difference using sets.
  3. Group a list of Person by city into a Map<String, List<Person>> with computeIfAbsent.
  4. Build a simple phone book: add, look up, delete, and list entries sorted by name.
  5. Reproduce ConcurrentModificationException, then fix it two different ways.
  6. Put a mutable object in a HashSet, change a field used by hashCode, then try to find it again. Explain the result.
