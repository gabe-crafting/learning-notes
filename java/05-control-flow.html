Control flow

Branching and looping — plus the modern switch, which is much nicer than the one you may have seen in older code.

if / else if / else

int score = 73;

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else {
    System.out.println("F");
}

The condition must be a boolean — unlike C or JavaScript, if (1) or if (someString) does not compile. That removes a whole family of bugs.

Always use braces, even for one-line bodies. The alternative has caused real security incidents.

Guard clauses beat nesting

// hard to read
public void process(Order order) {
    if (order != null) {
        if (order.isPaid()) {
            if (!order.isShipped()) {
                ship(order);
            }
        }
    }
}

// flat and obvious
public void process(Order order) {
    if (order == null)     return;
    if (!order.isPaid())   return;
    if (order.isShipped()) return;
    ship(order);
}

switch

The classic form

switch (day) {
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        System.out.println("Weekday");
        break;          // forget this and execution "falls through" to the next case
    case 6:
    case 7:
        System.out.println("Weekend");
        break;
    default:
        System.out.println("Invalid day");
}

The arrow form (Java 14+) — prefer this

switch (day) {
    case 1, 2, 3, 4, 5 -> System.out.println("Weekday");
    case 6, 7          -> System.out.println("Weekend");
    default            -> System.out.println("Invalid day");
}

No break, no fall-through, multiple labels per branch.

switch as an expression

String type = switch (day) {
    case 1, 2, 3, 4, 5 -> "Weekday";
    case 6, 7          -> "Weekend";
    default            -> throw new IllegalArgumentException("Bad day: " + day);
};

int daysInMonth = switch (month) {
    case FEBRUARY -> isLeap ? 29 : 28;
    case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30;
    default -> {
        int d = 31;             // a block branch needs yield
        yield d;
    }
};

A switch expression must produce a value on every path — the compiler enforces exhaustiveness, which is why switching over an enum with all constants covered needs no default.

Switch works on int, String, enum, and (Java 21+) on types via pattern matching:

String describe(Object o) {
    return switch (o) {
        case Integer i when i > 100 -> "big number " + i;
        case Integer i             -> "number " + i;
        case String s              -> "text of length " + s.length();
        case null                  -> "nothing";
        default                    -> "something else";
    };
}

Loops

for

for (int i = 0; i < 5; i++) {
    System.out.println(i);          // 0 1 2 3 4
}

for (int i = 10; i > 0; i -= 2) { ... }   // counting down
for (int i = 0, j = 10; i < j; i++, j--) { ... }

Read the header as: initialise once, test before each pass, update after each pass.

Enhanced for (for-each)

int[] numbers = {3, 1, 4, 1, 5};
for (int n : numbers) {
    System.out.println(n);
}

List<String> names = List.of("Ada", "Linus", "Grace");
for (String name : names) {
    System.out.println(name);
}

Use this whenever you do not need the index. It cannot modify the collection or the loop variable's slot — for that, use an indexed for or an Iterator.

while and do-while

int attempts = 0;
while (attempts < 3 && !connected) {
    connect();
    attempts++;
}

do {
    input = readLine();          // body runs at least once
} while (!input.equals("quit"));

Use while when the number of iterations is not known up front, for when it is.

break, continue and labels

for (String name : names) {
    if (name.isBlank()) continue;   // skip to the next iteration
    if (name.equals("stop")) break; // leave the loop entirely
    process(name);
}

outer:
for (int i = 0; i < rows; i++) {
    for (int j = 0; j < cols; j++) {
        if (grid[i][j] == target) {
            found = true;
            break outer;            // breaks BOTH loops
        }
    }
}

Labelled breaks are legal but rare; usually extracting the search into its own method that returns is clearer.

Infinite loops and off-by-one

for (int i = 0; i <= list.size(); i++)   // IndexOutOfBounds: last valid index is size() - 1
for (int i = 0; i < 10; i--)             // never ends
while (true) { ... }                     // deliberate; make sure something breaks or returns

Two questions catch most loop bugs: does the loop variable change on every path, and is the boundary < or <=?

Reading input

import java.util.Scanner;

Scanner scanner = new Scanner(System.in);
System.out.print("Your name: ");
String name = scanner.nextLine();
System.out.print("Your age: ");
int age = scanner.nextInt();
System.out.println("Hello " + name + ", " + age);
Scanner gotcha nextInt() consumes the number but not the newline after it, so a following nextLine() returns an empty string. Read everything with nextLine() and parse it yourself to avoid the whole class of problems.
Practice
  1. FizzBuzz: print 1–100, but multiples of 3 as "Fizz", of 5 as "Buzz", of both as "FizzBuzz".
  2. Rewrite a grade-letter if/else chain as a switch expression that returns a String.
  3. Number-guessing game: pick a random number 1–100 with new Random().nextInt(100) + 1, loop reading guesses, print higher/lower, stop when correct and report the number of attempts.
  4. Print a right-angled triangle of stars of height n using nested loops.
  5. Sum only the positive numbers in an array, skipping negatives with continue, and stop entirely if you hit a zero.
