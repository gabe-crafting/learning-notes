Methods

Named, reusable blocks of behaviour. Everything you write in Java lives inside one.

Anatomy

public static int add(int a, int b) {
    return a + b;
}
//  │      │     │    │     └──── parameters
//  │      │     │    └────────── method name
//  │      │     └─────────────── return type (void if it returns nothing)
//  │      └───────────────────── static: belongs to the class, not an instance
//  └──────────────────────────── access modifier

The signature is the name plus the parameter types — add(int, int). The return type is not part of it, which is why you cannot have two methods differing only in what they return.

Calling

int sum = add(2, 3);              // same class, static method
int sum2 = MathUtils.add(2, 3);   // static method on another class
int len = name.length();          // instance method: called on an object

Parameters are passed by value

Java is always pass-by-value. For objects, the value copied is the reference — so the method can change the object, but cannot change which object the caller's variable points at.

static void reassign(int n)       { n = 99; }
static void reassign(List<String> list) { list = new ArrayList<>(); }
static void mutate(List<String> list)   { list.add("added"); }

int x = 1;
reassign(x);                 // x is still 1

List<String> names = new ArrayList<>();
reassign(names);             // names is still the original, still empty
mutate(names);               // names now contains "added"

Overloading

Several methods may share a name if their parameter lists differ:

static int    max(int a, int b)       { return a > b ? a : b; }
static double max(double a, double b) { return a > b ? a : b; }
static int    max(int a, int b, int c){ return max(max(a, b), c); }

The compiler picks the most specific applicable version at compile time. Overload only when the methods truly do the same thing to different inputs; otherwise give them different names.

Varargs

static int sum(int... numbers) {      // numbers behaves like an int[]
    int total = 0;
    for (int n : numbers) total += n;
    return total;
}

sum();              // 0
sum(1, 2, 3);       // 6
sum(new int[]{1,2}) // 3

Only one varargs parameter is allowed and it must come last.

Return values

static String grade(int score) {
    if (score >= 90) return "A";
    if (score >= 80) return "B";
    return "C";                      // every path must return something
}

static void log(String message) {    // void: no return value
    System.out.println(message);
    if (message.isEmpty()) return;   // an early exit is still allowed
}

A method can only return one value. When you are tempted to return two, that is usually a signal to create a small class or record (lesson 12).

Scope and lifetime

public class Counter {
    private int total;               // field: lives as long as the object

    public void add(int amount) {
        int doubled = amount * 2;    // local: exists only during this call
        for (int i = 0; i < 3; i++) {
            int inner = i;           // exists only inside the loop body
        }
        // inner is not visible here
        total += doubled;
    }
}

A local variable shadows a field with the same name. That is what the this. prefix is for:

public void setName(String name) {
    this.name = name;                // this.name = the field, name = the parameter
}

static versus instance methods

staticinstance
Called on the class: Math.abs(-3)Called on an object: list.size()
Cannot use this or read instance fieldsHas access to the object's state
Good for pure helpers: parsing, formatting, mathsGood for behaviour tied to one object's data

A method that does not touch instance state can be static — but in application code most methods belong to objects, and frameworks like Spring rely on instances. Do not make everything static.

Recursion

static long factorial(int n) {
    if (n <= 1) return 1;            // base case — without it, StackOverflowError
    return n * factorial(n - 1);     // recursive case, moving toward the base
}

static int fibonacci(int n) {
    return n < 2 ? n : fibonacci(n - 1) + fibonacci(n - 2);
}

Every recursive method needs a base case and progress toward it. Java does not optimise tail calls, so deep recursion (tens of thousands of frames) overflows the stack — prefer loops for large inputs. Recursion shines on trees, directories, JSON and other nested structures.

Writing methods worth reading

  • One job. If the name needs an "and", split it.
  • Short. Anything past roughly 20 lines usually hides two ideas.
  • Named after what it does, not how. calculateDiscount, not doStuff2.
  • Few parameters. Three is plenty; more suggests a missing object.
  • No surprises. A method called getX() should not write to the database.
  • Validate input at the edges and fail loudly:
static double divide(int a, int b) {
    if (b == 0) throw new IllegalArgumentException("Cannot divide by zero");
    return (double) a / b;
}

Documenting with Javadoc

/**
 * Calculates the price after applying a percentage discount.
 *
 * @param price    the original price, must not be negative
 * @param percent  discount between 0 and 100
 * @return the discounted price
 * @throws IllegalArgumentException if percent is outside 0..100
 */
public static double applyDiscount(double price, double percent) { ... }

Document the why and the contract, not the obvious. IDEs show this on hover, which is most of its value.

Practice
  1. Write isPrime(int n) and use it to print all primes below 100.
  2. Overload a describe method for int, String and boolean, and observe which one the compiler picks for describe('a').
  3. Write a varargs average(double... values) that throws IllegalArgumentException when called with no arguments.
  4. Implement factorial both recursively and with a loop; compare them for n = 25 using long and explain the result.
  5. Refactor: take a 40-line main you have written and split it into three named methods.
