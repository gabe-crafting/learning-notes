Variables and types

Java's type system is the thing that catches your mistakes. Learn what the types are, how values are stored, and where beginners get burned.

Declaring a variable

int count = 10;                 // type, name, value
String name = "Ada";
final double TAX_RATE = 0.19;   // final = cannot be reassigned

A variable must be assigned before it is read. Local variables get no default value — the compiler rejects int x; System.out.println(x);.

The eight primitive types

Primitives are not objects. They hold a raw value directly, have a fixed size, and can never be null.

In practice you will use int, long, double and boolean almost exclusively. Use int unless the number can exceed two billion (ids, timestamps in milliseconds, money in minor units → long).

Readable numeric literals

int million   = 1_000_000;   // underscores are ignored by the compiler
int hex       = 0xFF;        // 255
int binary    = 0b1010;      // 10
long big      = 9_000_000_000L;   // L required: without it the literal is an int and overflows

Reference types

Everything that is not a primitive is a reference: String, arrays, your own classes, collections. The variable holds an address pointing to an object on the heap, and can be null.

String a = "hello";     // a refers to a String object
String b = null;        // b refers to nothing
int len = b.length();   // NullPointerException at runtime
NullPointerException The most common runtime error in Java. It means you called a method or read a field on a reference that was null. Java 14+ tells you exactly which part of the expression was null — read the message carefully. Lesson 17 covers Optional as a way of designing the problem away.

Wrapper classes

Each primitive has an object counterpart, needed anywhere an object is required (collections, generics, nullable values):

int → Integerlong → Long double → Doubleboolean → Boolean
char → Characterbyte → Byte short → Shortfloat → Float
List<Integer> numbers = new ArrayList<>();
numbers.add(5);                   // autoboxing: int 5 → Integer.valueOf(5)
int first = numbers.get(0);       // unboxing: Integer → int

Two traps come with wrappers:

Integer x = 127, y = 127;
System.out.println(x == y);       // true  — small Integers are cached
Integer p = 1000, q = 1000;
System.out.println(p == q);       // false — different objects!
System.out.println(p.equals(q));  // true  — compare values with equals

Integer maybe = null;
int value = maybe;                // NullPointerException on unboxing

Rule: compare objects with equals, never with ==. == on references asks "is this the same object", which is almost never the question you mean.

Stack, heap and what assignment copies

int a = 5;
int b = a;      // b is a copy; changing b never affects a
b = 9;          // a is still 5

int[] xs = {1, 2, 3};
int[] ys = xs;  // ys copies the *reference*, not the array
ys[0] = 99;     // xs[0] is now 99 as well — one array, two names

Primitives are copied by value; references are copied by value too, but the value is an address. Two variables can therefore point at the same object.

Conversion and casting

// widening — automatic, no data lost
int i = 100;
long l = i;
double d = l;

// narrowing — explicit cast, data may be lost
double price = 9.99;
int rounded = (int) price;      // 9   (truncates, does not round)
int big = 300;
byte small = (byte) big;        // 44  (overflow, silently)

Integer division and overflow

System.out.println(7 / 2);        // 3   — both operands are int
System.out.println(7 / 2.0);      // 3.5 — one operand is double
System.out.println(Integer.MAX_VALUE + 1);  // -2147483648, wraps around silently

Floating point is approximate

System.out.println(0.1 + 0.2);            // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);     // false

Never use double for money. Use BigDecimal, or store amounts as whole cents in a long:

BigDecimal total = new BigDecimal("19.99").multiply(BigDecimal.valueOf(3));
// construct from a String, not from a double, or you inherit the imprecision

Strings between types

String s = String.valueOf(42);         // "42"
String t = 42 + "";                    // works, but valueOf reads better
int n = Integer.parseInt("42");        // 42  — throws NumberFormatException on bad input
double d = Double.parseDouble("3.14");
boolean b = Boolean.parseBoolean("true");

var: inferred local types

Since Java 10 the compiler can infer the type of a local variable from its initialiser. The variable is still statically typed — this is not JavaScript's var.

var message = "hello";                      // String
var totals = new HashMap<String, Integer>(); // HashMap<String, Integer>
var count = 0;                               // int

var x;              // error: no initialiser, nothing to infer
var y = null;       // error

Use var when the type is obvious from the right-hand side and the line gets shorter. Avoid it when it hides information: var result = service.process(input); tells a reader nothing.

final

final int limit = 10;
limit = 11;                          // compile error

final List<String> names = new ArrayList<>();
names.add("Ada");                    // fine — the *reference* is final, not the object
names = new ArrayList<>();           // compile error

Marking fields and parameters final by default is a good habit: it documents that nothing reassigns them and prevents a class of bugs.

Practice
  1. In jshell, print the maximum and minimum of each integer type (Integer.MAX_VALUE, Long.MIN_VALUE, …).
  2. Write a program that reads two numbers from args, divides them, and prints both the integer division and the decimal division.
  3. Show the Integer caching surprise: two variables at 127 and two at 1000, compared with == and with equals.
  4. Compute 0.1 + 0.2 with double and again with BigDecimal. Print both.
  5. Take a double temperature and convert it to a whole-degree int two ways: casting and Math.round. Explain the difference for -2.5.
