Files, I/O and JSON

Reading and writing the outside world: files, streams, resources on the classpath, and the JSON your services will speak.

Path and Files

Use java.nio.file (Java 7+). The old java.io.File still appears in legacy code but has a worse API and poor error reporting.

Path path = Path.of("data", "orders.csv");        // OS-independent separator
Path abs = path.toAbsolutePath();
path.getFileName();   path.getParent();   path.resolve("sub.txt");

Files.exists(path);          Files.isDirectory(path);      Files.size(path);
Files.createDirectories(Path.of("out/reports"));
Files.copy(src, dest, StandardCopyOption.REPLACE_EXISTING);
Files.move(src, dest);
Files.delete(path);                  // throws if missing
Files.deleteIfExists(path);

Reading text

// whole file into a String — fine for small files
String content = Files.readString(path, StandardCharsets.UTF_8);

// all lines into a List
List<String> lines = Files.readAllLines(path, StandardCharsets.UTF_8);

// line by line, lazily — the right choice for large files
try (Stream<String> stream = Files.lines(path, StandardCharsets.UTF_8)) {
    stream.filter(line -> !line.isBlank())
          .map(String::strip)
          .forEach(System.out::println);
}

// classic buffered reader
try (BufferedReader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
    String line;
    while ((line = reader.readLine()) != null) {
        process(line);
    }
}
Always name the charset Without it you inherit the platform default, so the same code produces different results on your laptop and on the Linux server. StandardCharsets.UTF_8, every time.

Writing text

Files.writeString(path, "hello", StandardCharsets.UTF_8);
Files.write(path, lines, StandardCharsets.UTF_8);

// append instead of overwrite
Files.writeString(path, "more\n", StandardCharsets.UTF_8,
                  StandardOpenOption.CREATE, StandardOpenOption.APPEND);

try (BufferedWriter writer = Files.newBufferedWriter(path, StandardCharsets.UTF_8)) {
    writer.write("first line");
    writer.newLine();
    writer.write("second line");
}

Binary data

byte[] bytes = Files.readAllBytes(path);
Files.write(path, bytes);

try (InputStream in = Files.newInputStream(src);
     OutputStream out = Files.newOutputStream(dest)) {
    in.transferTo(out);              // Java 9+
}

The stream class hierarchy, briefly

BytesCharacters
ReadInputStreamReader
WriteOutputStreamWriter

They wrap each other — a decorator design. BufferedReader around an InputStreamReader around a FileInputStream. Buffering matters: unbuffered character-by-character reads are orders of magnitude slower.

try-with-resources, again

try (var reader = Files.newBufferedReader(path)) {
    ...
} catch (NoSuchFileException e) {
    log.warn("Missing file {}", path);
} catch (IOException e) {
    throw new UncheckedIOException(e);
}

Any AutoCloseable declared in the parentheses is closed automatically, in reverse order, even when an exception is thrown. Never leave a stream unclosed — open file handles leak and eventually the process runs out.

Reading a resource from the classpath

Files inside src/main/resources are packaged into the jar, so they cannot be read with a file path at runtime. Load them as a resource stream instead:

try (InputStream in = getClass().getResourceAsStream("/config.properties")) {
    Properties props = new Properties();
    props.load(in);
    String url = props.getProperty("db.url");
}

String text;
try (var in = MyClass.class.getResourceAsStream("/data/seed.json")) {
    text = new String(in.readAllBytes(), StandardCharsets.UTF_8);
}

A small CSV example

record Order(String id, String customer, BigDecimal total) { }

List<Order> readOrders(Path csv) throws IOException {
    try (Stream<String> lines = Files.lines(csv, StandardCharsets.UTF_8)) {
        return lines.skip(1)                          // header
                    .filter(line -> !line.isBlank())
                    .map(line -> line.split(","))
                    .map(f -> new Order(f[0].strip(), f[1].strip(), new BigDecimal(f[2].strip())))
                    .toList();
    }
}

Splitting on commas breaks the moment a field contains a comma or a quote. For anything beyond a toy, use a library — OpenCSV or Apache Commons CSV.

JSON with Jackson

Jackson is the de-facto standard and is what Spring Boot uses under the hood, so learning it now pays off in the next course.

<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.17.1</version>
</dependency>
record Product(String name, BigDecimal price, boolean available) { }

ObjectMapper mapper = new ObjectMapper();           // create once, reuse — it is thread-safe

// object → JSON
String json = mapper.writeValueAsString(product);
mapper.writerWithDefaultPrettyPrinter().writeValueAsString(product);
mapper.writeValue(Path.of("product.json").toFile(), product);

// JSON → object
Product p = mapper.readValue(json, Product.class);
List<Product> list = mapper.readValue(json, new TypeReference<List<Product>>() {});

// unknown fields
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

// java.time support
mapper.registerModule(new JavaTimeModule());
public record Customer(
        @JsonProperty("customer_id") String id,      // different name in JSON
        String name,
        @JsonIgnore String internalNote) { }

Practice
  1. Write a program that counts lines, words and characters in a file given as an argument.
  2. Read a CSV of products, filter those under a given price, and write the result to a new CSV.
  3. Load a .properties file from src/main/resources and print every key and value.
  4. Serialise a list of records to pretty JSON with Jackson, write it to disk, read it back and confirm the objects are equal.
  5. Walk a directory tree and report the ten largest files.
  6. Deliberately forget try-with-resources, then use it — and explain what could go wrong in a long-running server without it.
