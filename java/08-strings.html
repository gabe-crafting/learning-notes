Strings and text

Strings are objects, they are immutable, and that single fact explains most of their behaviour.

Creating strings

String a = "hello";                  // literal — goes into the string pool
String b = new String("hello");      // new object every time — avoid
String c = String.valueOf(42);       // "42"
String d = "";                       // empty, not null

Immutability

String s = "hello";
s.toUpperCase();                     // returns "HELLO" — s is unchanged
System.out.println(s);               // hello

s = s.toUpperCase();                 // reassignment is how you "change" a string
System.out.println(s);               // HELLO

Every String method returns a new string. Forgetting to use the return value is one of the most common beginner bugs.

Immutability is why strings are safe to share across threads, safe as map keys, and why the JVM can pool identical literals.

Comparing strings

String x = "hello";
String y = "hello";
String z = new String("hello");

x == y                    // true  — both point at the same pooled literal
x == z                    // false — different objects
x.equals(z)               // true  — same characters  ← use this
x.equalsIgnoreCase("HELLO")  // true
x.compareTo("world")      // negative: "hello" sorts before "world"
Never compare strings with == It happens to work for literals, which makes the bug survive testing and appear in production the moment a string arrives from a file, a database or a web request.

Guarding against null, put the constant first:

if ("admin".equals(role)) { ... }        // safe even when role is null
if (Objects.equals(a, b)) { ... }        // safe both ways

The methods you will actually use

String s = "  Hello, World  ";

s.length()                    // 17
s.trim()                      // "Hello, World"  (removes ASCII whitespace)
s.strip()                     // same, Unicode-aware (Java 11+) — prefer this
s.isEmpty()                   // length == 0
s.isBlank()                   // empty or only whitespace (Java 11+)

"Hello".charAt(0)             // 'H'
"Hello".indexOf("l")          // 2      (-1 if not found)
"Hello".lastIndexOf("l")      // 3
"Hello".contains("ell")       // true
"Hello".startsWith("He")      // true
"Hello".endsWith("lo")        // true

"Hello".substring(2)          // "llo"
"Hello".substring(1, 3)       // "el"   (start inclusive, end exclusive)
"Hello".replace('l', 'L')     // "HeLLo"
"a,b,c".split(",")            // ["a", "b", "c"]
String.join("-", "a", "b")    // "a-b"
"Hello".toUpperCase()         // "HELLO"
"ab".repeat(3)                // "ababab"  (Java 11+)
"a\nb".lines()                // stream of lines (Java 11+)
"Hello".toCharArray()         // ['H','e','l','l','o']

Escapes and text blocks

String quote = "She said \"hi\"";
String path  = "C:\\Users\\gabe";     // backslash must be escaped
String multi = "line one\nline two";  // \n newline, \t tab, \\ backslash

Java 15+ has text blocks, which make embedded JSON, SQL and HTML readable:

String json = """
    {
      "name": "Ada",
      "role": "engineer"
    }
    """;

Indentation common to all lines is stripped, so the block lines up with your code without polluting the value.

Building strings efficiently

// bad in a loop: creates a new String on every iteration
String result = "";
for (String word : words) {
    result += word + " ";
}

// good: one mutable buffer
StringBuilder sb = new StringBuilder();
for (String word : words) {
    sb.append(word).append(' ');
}
String result = sb.toString();

For a handful of concatenations, + is fine — the compiler optimises it. Inside a loop, use StringBuilder. (StringBuffer is the thread-safe, slower twin; you almost never need it.)

Joining a collection is nicer still:

String csv = String.join(", ", names);
String csv2 = names.stream().collect(Collectors.joining(", ", "[", "]"));

Formatting

String.format("%s is %d years old", "Ada", 36)   // "Ada is 36 years old"
String.format("%.2f", 3.14159)                    // "3.14"
String.format("%,d", 1234567)                     // "1,234,567"
String.format("%5d|", 42)                         // "   42|"  right-aligned width 5
String.format("%-5d|", 42)                        // "42   |"  left-aligned
System.out.printf("%s: %d%n", "count", 7);        // printf writes directly, %n = newline

"Hello %s".formatted("world")                     // Java 15+, same as String.format
%sany object (calls toString())
%dinteger
%ffloating point
%bboolean
%nplatform newline
%%a literal percent sign

Parsing and converting

int n = Integer.parseInt("42");            // NumberFormatException if not numeric
double d = Double.parseDouble("3.14");
String s = String.valueOf(42);
String t = Integer.toString(42);
char c = "abc".charAt(1);
int digit = Character.getNumericValue('7');  // 7
Character.isDigit('7')     Character.isLetter('a')     Character.toUpperCase('a')

Characters, code points and encoding

A char is 16 bits — enough for most characters, but emoji and some scripts need two chars (a "surrogate pair"). So "👋".length() is 2. When correctness matters for non-Latin text, work with code points:

"👋".codePointCount(0, "👋".length())    // 1
text.codePoints().forEach(...);

When reading or writing files, always state the charset — StandardCharsets.UTF_8 — rather than relying on the platform default (lesson 18).

Regular expressions, briefly

"hello123".matches("[a-z]+\\d+")            // true
"a1b2".replaceAll("\\d", "#")               // "a#b#"
"a, b,c".split("\\s*,\\s*")                 // ["a", "b", "c"]

Pattern p = Pattern.compile("(\\w+)@(\\w+)\\.com");   // compile once, reuse
Matcher m = p.matcher("write to ada@example.com now");
if (m.find()) {
    m.group(1);   // "ada"
    m.group(2);   // "example"
}

Remember that in a Java string, a backslash must itself be escaped: the regex \d is written "\\d".
