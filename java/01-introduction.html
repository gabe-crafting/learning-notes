What Java is and how it runs

Before the syntax, the machinery: what happens between the text you type and a program that runs.

What Java is

Java is a statically typed, object-oriented, compiled language that runs on a virtual machine. Unpacking that:

  • Statically typed — every variable has a type known at compile time, and the compiler refuses code that misuses it. A whole class of mistakes is caught before the program ever runs.
  • Object-oriented — code lives inside classes; data and the behaviour that operates on it are bundled together.
  • Compiled to bytecode — not to machine code for your specific CPU, but to an intermediate format that any Java Virtual Machine can execute.
  • Garbage collected — you allocate objects; you never free them. The JVM reclaims memory that nothing references any more.

It is the default choice for backend services in banking, insurance, telecom, retail and large enterprises generally — which is why "Java + Spring" is one of the most common junior job descriptions in the market.

JDK, JRE, JVM

Three acronyms that beginners mix up constantly. They are nested:

TermWhat it isDo you need it?
JVM (Java Virtual Machine) The program that executes bytecode. It is what makes "write once, run anywhere" true: the same .class file runs on Windows, Linux and macOS. To run Java
JRE (Java Runtime Environment) JVM + the standard library (String, List, and thousands more classes). To run Java
JDK (Java Development Kit) JRE + the compiler (javac) and developer tools (jar, javadoc, jshell, debugger). To write Java — install this one

From source to running program

Main.java        →   javac   →   Main.class        →    java     →   running program
(your source)      (compiler)    (JVM bytecode)      (the JVM)

The compiler checks types, resolves names and produces bytecode. The JVM loads that bytecode, verifies it, and interprets it — then its JIT (just-in-time) compiler notices which methods run often and compiles those to native machine code while the program is running. That is why a Java service is slow for its first few seconds and fast afterwards.

Your first program

Create a file called Main.java. The public class name must match the file name — that is a rule, not a convention.

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
    }
}

Run it:

javac Main.java     # produces Main.class
java Main           # prints: Hello, Java

Since Java 11 you can skip the explicit compile step for a single file: java Main.java.

Reading that signature word by word

publicVisible from anywhere. The JVM has to be able to call it.
staticBelongs to the class, not to an instance — so it can be called without creating a Main object first.
voidReturns nothing.
mainThe name the JVM looks for when starting a program.
String[] argsCommand-line arguments. java Main a b gives args = ["a", "b"].

Anatomy of a real source file

package com.example.shop;          // 1. where this class lives

import java.util.List;             // 2. classes from elsewhere that this file uses

/**
 * 3. Javadoc: documentation for the class.
 */
public class Order {               // 4. the type itself

    private final List<String> items;   // field

    public Order(List<String> items) {  // constructor
        this.items = items;
    }

    public int size() {            // method
        return items.size();       // statements end with a semicolon
    }
}
  • Packages mirror folders: com.example.shop.Order lives in com/example/shop/Order.java. They exist to keep names unique — reversed domain names are the convention.
  • Imports save typing. java.lang (String, Integer, System, Math…) is imported automatically.
  • Comments: // to end of line, /* block */, and /** javadoc */ which tools turn into documentation.

Which Java version

Java releases every six months, but only some releases are LTS (long-term support): 8, 11, 17, 21, 25. Companies stay on LTS versions. Learn on 21; expect to meet 8, 11 and 17 in real codebases. Older code just means fewer of the modern conveniences (records, var, switch expressions) — the fundamentals are unchanged.

Practice
  1. Write, compile and run Main.java from the terminal — not from an IDE. You should see the Main.class file appear.
  2. Print each command-line argument: run java Main hello world and make it print both.
  3. Run java -version and javac -version. Note which version you have; you will need to match it in build files later.
  4. Deliberately break something — remove a semicolon, misspell String — and read the compiler error. Getting comfortable reading errors early pays for itself many times over.
