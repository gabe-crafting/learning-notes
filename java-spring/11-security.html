Spring Security basics

Who are you (authentication), and what may you do (authorisation). Security is the area where copying a random tutorial does the most damage, so go slowly here.

Adding it

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

The moment it is on the classpath, every endpoint requires authentication, a login form appears, and a generated password is printed in the startup log. That is deliberate: secure by default, then you open what you choose.

The filter chain

request
  → SecurityFilterChain
      → CorsFilter
      → CsrfFilter
      → your authentication filter (JWT, session, basic)
      → AuthorizationFilter        ← decides allow / deny
  → DispatcherServlet → your controller

Security happens before Spring MVC. That is why a 401 or 403 never reaches your @RestControllerAdvice unless you configure the entry points to produce it.

Configuring the rules

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())                      // safe ONLY for a stateless token API
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/actuator/health").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/tasks/**").hasAnyRole("USER", "ADMIN")
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())                  // deny-by-default, always last
            .httpBasic(Customizer.withDefaults())
            .build();
    }

    @Bean
    PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

Order matters: the first matching rule wins, so put specific paths before general ones and finish with anyRequest().authenticated().

About disabling CSRF CSRF protection matters when the browser sends credentials automatically — cookies or session ids. For a stateless API authenticated by an Authorization header, it is not applicable and is normally disabled. If you use cookie-based sessions, leave it on and send the token from the frontend.

Users and passwords

@Service
public class DbUserDetailsService implements UserDetailsService {

    private final UserRepository repository;

    public DbUserDetailsService(UserRepository repository) { this.repository = repository; }

    @Override
    public UserDetails loadUserByUsername(String email) {
        AppUser user = repository.findByEmail(email)
                .orElseThrow(() -> new UsernameNotFoundException("Bad credentials"));

        return User.withUsername(user.getEmail())
                   .password(user.getPasswordHash())     // the HASH, never the password
                   .roles(user.getRoles().toArray(String[]::new))
                   .build();
    }
}
String hash = passwordEncoder.encode(rawPassword);          // on registration
boolean ok  = passwordEncoder.matches(rawPassword, hash);   // never compare strings yourself
  • Store only BCrypt (or Argon2) hashes. Never plain text, never MD5 or plain SHA.
  • Never log a password, a token, or a hash.
  • Return the same error for "unknown user" and "wrong password" — otherwise you have built an account enumerator.
  • Rate-limit login attempts.

JWT authentication

The common pattern for a stateless API: the client logs in once, receives a signed token, and sends it on every request.

POST /api/auth/login  {"email": "...", "password": "..."}
→ 200 {"token": "eyJhbGciOiJIUzI1NiJ9...", "expiresIn": 3600}

GET /api/tasks
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
@Component
public class JwtService {

    private final SecretKey key;
    private final Duration ttl;

    public JwtService(@Value("${app.jwt.secret}") String secret,
                      @Value("${app.jwt.ttl:1h}") Duration ttl) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.ttl = ttl;
    }

    public String generate(UserDetails user) {
        Instant now = Instant.now();
        return Jwts.builder()
                .subject(user.getUsername())
                .claim("roles", user.getAuthorities().stream().map(Object::toString).toList())
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plus(ttl)))
                .signWith(key)
                .compact();
    }

    public Jws<Claims> parse(String token) {        // throws if signature or expiry is invalid
        return Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
    }
}
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwt;
    private final UserDetailsService users;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {

        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            try {
                String email = jwt.parse(header.substring(7)).getPayload().getSubject();
                UserDetails user = users.loadUserByUsername(email);
                var auth = new UsernamePasswordAuthenticationToken(
                        user, null, user.getAuthorities());
                SecurityContextHolder.getContext().setAuthentication(auth);
            } catch (JwtException e) {
                log.debug("Invalid token", e);      // leave the context unauthenticated
            }
        }
        chain.doFilter(request, response);
    }
}
.addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)

Practical notes: keep the secret out of the repository and at least 256 bits; keep access tokens short-lived (15–60 minutes) with a refresh token for renewal; remember that a JWT cannot be revoked before expiry unless you keep a denylist. For anything beyond a learning project, prefer an existing identity provider (Keycloak, Auth0, Cognito) with spring-boot-starter-oauth2-resource-server over hand-rolled tokens.

Method security

@Configuration
@EnableMethodSecurity
public class MethodSecurityConfig { }
@PreAuthorize("hasRole('ADMIN')")
public void deleteUser(Long id) { ... }

@PreAuthorize("hasAuthority('SCOPE_tasks:write')")
public TaskResponse create(CreateTaskRequest request) { ... }

@PreAuthorize("#userId == authentication.name or hasRole('ADMIN')")
public List<TaskResponse> tasksOf(String userId) { ... }

@PostAuthorize("returnObject.ownerId == authentication.name")
public TaskResponse get(Long id) { ... }

Remember the proxy rule: @PreAuthorize on a method called from inside the same bean does nothing.

Roles versus authorities

hasRole("ADMIN")        → checks for the authority "ROLE_ADMIN"   (the prefix is added for you)
hasAuthority("ROLE_ADMIN")  → the same check, written out
hasAuthority("tasks:write") → a fine-grained permission

Roles are coarse ("who you are"), authorities fine ("what you may do"). Mixing them up is the usual cause of "I have the role but I get 403".

Testing secured endpoints

@WebMvcTest(TaskController.class)
class TaskControllerSecurityTest {

    @Autowired MockMvc mvc;

    @Test
    void anonymousIsRejected() throws Exception {
        mvc.perform(get("/api/tasks")).andExpect(status().isUnauthorized());
    }

    @Test
    @WithMockUser(roles = "USER")
    void userCanList() throws Exception {
        mvc.perform(get("/api/tasks")).andExpect(status().isOk());
    }

    @Test
    @WithMockUser(roles = "USER")
    void userCannotDelete() throws Exception {
        mvc.perform(delete("/api/tasks/1").with(csrf())).andExpect(status().isForbidden());
    }
}

Write the negative tests. An endpoint that is accidentally public passes every happy-path test.

The junior checklist

  • Deny by default; open specific paths deliberately.
  • Hash passwords with BCrypt; never store or log secrets.
  • Validate every input — Bean Validation is a security control, not just tidiness.
  • Use parameterised queries; JPA does this for you unless you concatenate strings into a native query.
  • Do not put sensitive data in URLs — they end up in logs and browser history.
  • HTTPS everywhere; secure, http-only cookies if you use sessions.
  • Check authorisation on the object, not just the endpoint: "may this user edit this task?"
  • Keep dependencies patched — known CVEs are the most common real breach.
Practice
  1. Add Spring Security, observe every endpoint locked, then permit /actuator/health only.
  2. Store users in the database with BCrypt hashes and implement UserDetailsService.
  3. Implement login returning a JWT and a filter that authenticates from the header.
  4. Restrict DELETE /api/tasks/** to ADMIN and prove with a test that USER gets 403.
  5. Add an ownership check so a user can only read their own tasks — and test the negative case.
  6. Try an expired and a tampered token and confirm both are rejected.
