Your first Spring Boot app

Generate a project, understand every file in it, and get an HTTP endpoint responding in about ten minutes.

Generate the project

Go to start.spring.io (or use the IntelliJ "Spring Initializr" wizard, which is the same thing) and choose:

ProjectMaven
LanguageJava
Spring Bootthe latest 3.x release (not a SNAPSHOT or milestone)
Groupcom.example
Artifacttasks
PackagingJar
Java21
DependenciesSpring Web, Spring Boot DevTools, Validation

Download, unzip, open in your IDE. You can also do it from the terminal:

curl https://start.spring.io/starter.zip \
  -d dependencies=web,devtools,validation \
  -d javaVersion=21 -d type=maven-project \
  -d groupId=com.example -d artifactId=tasks \
  -o tasks.zip

What you got

tasks/
├── pom.xml
├── mvnw, mvnw.cmd, .mvn/         the Maven wrapper — commit these
└── src/
    ├── main/
    │   ├── java/com/example/tasks/TasksApplication.java
    │   └── resources/
    │       ├── application.properties
    │       ├── static/            served as-is at /
    │       └── templates/         server-rendered views (not needed for a REST API)
    └── test/java/com/example/tasks/TasksApplicationTests.java

pom.xml

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.3.2</version>
</parent>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>   <!-- no version needed -->
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>   <!-- builds the runnable jar -->
        </plugin>
    </plugins>
</build>

The parent pins compatible versions for everything, which is why your dependencies have no <version> tags. spring-boot-starter-web alone brings in Spring MVC, Jackson, validation support and an embedded Tomcat.

The main class

package com.example.tasks;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class TasksApplication {

    public static void main(String[] args) {
        SpringApplication.run(TasksApplication.class, args);
    }
}

@SpringBootApplication is three annotations in one:

  • @SpringBootConfiguration — this class may define beans.
  • @EnableAutoConfiguration — configure things based on what is on the classpath.
  • @ComponentScan — find annotated classes in this package and below.
Keep the main class at the root package Component scanning starts from its package. Put your classes in com.example.tasks.*. A class in com.other will simply never be found, and the error ("no qualifying bean") will not tell you why.

Your first endpoint

package com.example.tasks;

import org.springframework.web.bind.annotation.*;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "world") String name) {
        return "Hello, " + name;
    }
}
curl http://localhost:8080/hello
curl "http://localhost:8080/hello?name=Gabe"

Returning JSON

record Task(Long id, String title, boolean done) { }

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    @GetMapping
    public List<Task> all() {
        return List.of(new Task(1L, "Learn Spring", false),
                       new Task(2L, "Build an API", false));
    }
}
$ curl http://localhost:8080/api/tasks
[{"id":1,"title":"Learn Spring","done":false},{"id":2,"title":"Build an API","done":false}]

You wrote no serialisation code. Jackson is on the classpath, so Spring converts the returned object to JSON automatically — that is auto-configuration doing its job.

Configuration

src/main/resources/application.properties (or rename it to application.yml):

server.port=8081
spring.application.name=tasks
logging.level.com.example.tasks=DEBUG
server:
  port: 8081
spring:
  application:
    name: tasks
logging:
  level:
    com.example.tasks: DEBUG

YAML is the more common choice in real projects because nested configuration becomes readable. Lesson 4 goes into detail.

DevTools

With spring-boot-devtools on the classpath, the app restarts automatically when classes are recompiled (in IntelliJ: Build → Recompile, or enable build-on-save). It is a development-only dependency and is disabled in a packaged jar.

The test that came with it

@SpringBootTest
class TasksApplicationTests {

    @Test
    void contextLoads() { }
}

It looks trivial and is not: it starts the whole application context, so it fails whenever a bean cannot be created, a required property is missing, or two beans conflict. Keep it.

Packaging

./mvnw clean package
java -jar target/tasks-0.0.1-SNAPSHOT.jar

One self-contained file with the web server inside — this is what you deploy.

Reading startup failures

***************************
APPLICATION FAILED TO START
***************************

Description:
Web server failed to start. Port 8080 was already in use.

Action:
Identify and stop the process that's listening on port 8080 or configure
this application to listen on another port.

Boot's failure analysers turn common problems into readable advice. Read the "Description" and "Action" before scrolling into the stack trace.

Practice
  1. Generate the project and get it running. Confirm the banner and the port in the log.
  2. Add /hello and call it with and without the name parameter.
  3. Return a record from an endpoint and inspect the JSON. Add a LocalDate field and see how it is rendered.
  4. Change the port to 9090 in application.yml and restart.
  5. Move a controller into a package outside com.example.tasks, observe the 404, then move it back. Now you have seen the component-scan rule fail for yourself.
  6. Package the jar and run it with java -jar.
