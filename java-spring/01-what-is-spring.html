What Spring is and why it exists

Before any annotation: the problem Spring solves, and the one idea the whole framework is built on.

The problem

Write a service by hand and you spend most of your time wiring rather than solving the business problem:

public class OrderController {
    private final OrderService service =
        new OrderService(
            new JdbcOrderRepository(
                new HikariDataSource(readConfigSomehow())),
            new StripePaymentGateway(System.getenv("STRIPE_KEY")),
            new SmtpEmailSender("smtp.example.com", 587));
}

Every class knows how to construct its dependencies. Change the database and you edit twenty files. Test the controller and you need a real database and a real payment provider. Add a second thing that needs the same DataSource and you have two connection pools.

Inversion of control

Spring turns it around: a class declares what it needs, and something else supplies it.

@Service
public class OrderService {

    private final OrderRepository repository;
    private final PaymentGateway gateway;

    public OrderService(OrderRepository repository, PaymentGateway gateway) {
        this.repository = repository;      // Spring passes these in
        this.gateway = gateway;
    }
}

That is dependency injection, and it is the whole trick. The class no longer decides which implementation it gets, so:

  • Swapping an implementation is a configuration change, not a code change.
  • Testing means passing a mock into the constructor — no framework required.
  • One shared instance is created once and reused, instead of each class making its own.

The application context

At startup Spring builds an application context: a registry of objects it manages, called beans. It scans your packages for annotated classes, works out the dependency graph, constructs everything in the right order, and hands each object its collaborators.

Startup:
  scan com.example.**
  found: OrderController, OrderService, JdbcOrderRepository, StripeGateway
  OrderService needs OrderRepository  → inject JdbcOrderRepository
  OrderController needs OrderService  → inject OrderService
  context ready — 4 beans

Everything else Spring does — transactions, security, HTTP endpoints, scheduling — is built on top of this by wrapping beans in extra behaviour (a proxy) as they are created.

Nobody starts a new project with plain Spring today. "Learning Spring" in practice means learning Spring Boot, which is what the rest of this course does.

What Boot actually does

  • Starters — one dependency (spring-boot-starter-web) pulls in a consistent set of libraries with versions that work together.
  • Auto-configuration — it inspects the classpath and configures what it finds. An H2 driver present and no DataSource defined? It creates one. You define your own? It backs off.
  • Embedded server — Tomcat runs inside your jar; java -jar app.jar starts a web service.
  • Externalised configuration — application.yml, environment variables, profiles.
  • Actuator — health checks and metrics endpoints for free.

Aspect-oriented programming, in one paragraph

Some concerns — transactions, security checks, caching, metrics — cut across many methods. Rather than repeating them, Spring wraps your bean in a proxy: an object with the same interface that runs extra code before and after your method.

@Transactional
public void placeOrder(Order order) { ... }

// proxy: begin transaction → your method → commit (or roll back on exception)
The proxy gotcha you will hit Because the behaviour lives in the proxy, calling an annotated method from another method of the same class bypasses it entirely — no transaction, no security check. The call has to come from outside the bean. Remember this; it explains a bug you will otherwise spend an afternoon on.

Why the industry uses it

Not because it is elegant — because it is boring in the right way. A Spring Boot service in one company looks like a Spring Boot service in another: same layout, same annotations, same configuration files. A developer moves teams and is productive in days. That standardisation is why the job adverts all say Spring, and why this course is worth your time.
