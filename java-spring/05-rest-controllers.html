REST controllers

The web layer: mapping HTTP requests to methods, reading input, and returning the right status code.

A complete controller

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    private final TaskService service;

    public TaskController(TaskService service) {
        this.service = service;
    }

    @GetMapping
    public List<TaskResponse> list(@RequestParam(required = false) Boolean done) {
        return service.findAll(done);
    }

    @GetMapping("/{id}")
    public TaskResponse getOne(@PathVariable Long id) {
        return service.findById(id);            // throws if missing → 404 (lesson 7)
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public TaskResponse create(@RequestBody @Valid CreateTaskRequest request) {
        return service.create(request);
    }

    @PutMapping("/{id}")
    public TaskResponse update(@PathVariable Long id,
                               @RequestBody @Valid UpdateTaskRequest request) {
        return service.update(id, request);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable Long id) {
        service.delete(id);
    }
}

@RestController = @Controller + @ResponseBody: every return value is serialised to the response body (JSON, via Jackson) rather than resolved as a view name.

Mapping annotations

@GetMapping     @PostMapping    @PutMapping     @PatchMapping   @DeleteMapping

@RequestMapping(value = "/search", method = RequestMethod.GET)   // the general form
@GetMapping(value = "/{id}", produces = MediaType.APPLICATION_JSON_VALUE)
@PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE)

Class-level @RequestMapping prefixes every method in the class.

Getting data out of the request

Path variables

@GetMapping("/{id}")
public TaskResponse get(@PathVariable Long id) { ... }

@GetMapping("/{userId}/tasks/{taskId}")
public TaskResponse get(@PathVariable Long userId, @PathVariable Long taskId) { ... }

@GetMapping("/{id}")
public TaskResponse get(@PathVariable("id") Long taskId) { ... }   // when names differ

Query parameters

// GET /api/tasks?done=true&page=2&size=20&tag=home&tag=urgent
@GetMapping
public List<TaskResponse> list(
        @RequestParam(required = false) Boolean done,
        @RequestParam(defaultValue = "0") int page,
        @RequestParam(defaultValue = "20") int size,
        @RequestParam List<String> tag) { ... }

A missing parameter without required = false or a default produces 400 Bad Request — which is usually what you want.

Request body

public record CreateTaskRequest(String title, String description, LocalDate dueDate) { }

@PostMapping
public TaskResponse create(@RequestBody CreateTaskRequest request) { ... }

Jackson maps the JSON onto the record by component name. Unknown fields are ignored by default in Boot; missing ones become null (or 0 for primitives — a good reason to prefer wrapper types in request records).

Status codes

200 OKSuccessful GET, PUT, PATCH
201 CreatedPOST that created a resource — add a Location header
204 No ContentSuccessful DELETE, or an update with nothing to return
400 Bad RequestMalformed or invalid input
401 UnauthorizedNot authenticated (you are nobody)
403 ForbiddenAuthenticated but not allowed (you are someone, but not allowed)
404 Not FoundNo such resource
409 ConflictViolates current state — duplicate email, already cancelled
422 Unprocessable EntitySyntactically fine but semantically invalid (some teams prefer this to 400)
500 Internal Server ErrorYour bug. Never return this deliberately.

Three ways to set one

// 1. annotation — simplest when it is always the same
@ResponseStatus(HttpStatus.CREATED)

// 2. ResponseEntity — when it varies, or you need headers
@PostMapping
public ResponseEntity<TaskResponse> create(@RequestBody @Valid CreateTaskRequest request) {
    TaskResponse created = service.create(request);
    URI location = ServletUriComponentsBuilder.fromCurrentRequest()
            .path("/{id}").buildAndExpand(created.id()).toUri();
    return ResponseEntity.created(location).body(created);
}

Designing the URLs

GET    /api/tasks              list
POST   /api/tasks              create
GET    /api/tasks/42           read one
PUT    /api/tasks/42           replace
PATCH  /api/tasks/42           partial update
DELETE /api/tasks/42           delete
GET    /api/users/7/tasks      sub-resource
POST   /api/tasks/42/complete  a state transition that is not CRUD
  • Nouns, not verbs: /api/tasks, never /api/getTasks.
  • Plural collection names, consistently.
  • Lowercase with hyphens: /api/task-lists.
  • Version at the root when you need to: /api/v1/tasks.
  • Filtering, sorting and paging are query parameters, not paths.
  • GET must never change state — it is retried and cached by proxies.

Paging and sorting

@GetMapping
public Page<TaskResponse> list(@PageableDefault(size = 20, sort = "createdAt") Pageable pageable) {
    return service.findAll(pageable);
}
// GET /api/tasks?page=0&size=20&sort=dueDate,desc

Spring builds the Pageable from the query string, and the JSON response includes content, totalElements, totalPages and number. Always page collection endpoints — "it is only a few hundred rows" ages badly.

Content negotiation and CORS

@CrossOrigin(origins = "http://localhost:3000")     // per controller — fine for development
@RestController
public class TaskController { ... }
@Configuration
public class WebConfig implements WebMvcConfigurer {      // global, preferred
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("https://app.example.com")
                .allowedMethods("GET", "POST", "PUT", "DELETE");
    }
}

A browser calling your API from another origin will fail without this — and the error appears in the browser console, not in your server log. It is the number one "my frontend cannot reach my backend" cause.

Testing an endpoint by hand

curl http://localhost:8080/api/tasks

curl -X POST http://localhost:8080/api/tasks \
     -H "Content-Type: application/json" \
     -d '{"title":"Write tests","dueDate":"2026-10-01"}'

curl -i -X DELETE http://localhost:8080/api/tasks/42     # -i shows the status line and headers

An HTTP file in your IDE (requests.http) or a Bruno/Postman collection is worth keeping in the repo so the whole team has the same examples.

What does not belong in a controller

@PostMapping
public TaskResponse create(@RequestBody CreateTaskRequest request) {
    // ✗ business rules, database calls, email sending, transaction handling
    // ✓ take input, delegate to the service, shape the response
    return service.create(request);
}

A controller should be boring and thin. Everything interesting belongs in the service layer — which is the next lesson.

Practice

  2. Return 201 with a Location header from the create endpoint and check it with curl -i.
  3. Add filtering by done and by tag using query parameters.
  4. Add paging with Pageable and inspect the JSON envelope.
  5. Call a POST endpoint with a malformed JSON body and note the status code and the message.
  6. Design URLs for a blog: posts, comments on a post, publishing a draft. Justify each one.
