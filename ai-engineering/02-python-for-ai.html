Python for AI engineers

You already know how to program. This is the subset of Python this job actually uses, aimed at someone arriving from JavaScript, Java or C#.

Why Python

Every model provider ships a Python SDK first, every retrieval and evaluation library is Python, and every research artifact you might want to use is Python. TypeScript is a perfectly good second language here — SDKs exist for all the major providers, and if you are building the UI you will write it anyway — but the ecosystem depth is in Python. Learn enough of both to be dangerous; write the AI backend in Python.

Comprehensions are the Python equivalent of map/filter chains, and generators matter here because ingestion pipelines routinely process files too large to hold in memory.

Python is dynamically typed, but professional code is annotated. Types are not enforced at runtime — they document intent, drive editor completion, and let mypy/pyright catch mistakes.

Pydantic: the library that makes LLM output usable

Pydantic validates and coerces data against a declared model. In AI work it does three jobs: it defines the JSON schema you send to the model, it validates what comes back, and it types your application config.

from pydantic import BaseModel, Field, ValidationError
from datetime import date

class Invoice(BaseModel):
    vendor: str
    invoice_number: str
    issued: date
    total: float = Field(gt=0, description="Total amount including tax")
    line_items: list[str] = []

# parse untrusted JSON — from a model, an API, a file
try:
    invoice = Invoice.model_validate_json(raw_json)
except ValidationError as e:
    print(e.errors())      # structured, per-field failures

invoice.model_dump()            # → dict
invoice.model_dump_json()       # → JSON string
Invoice.model_json_schema()     # → JSON Schema, which is what you hand the model

That last line is the reason Pydantic is everywhere in this field: your Python class is the contract you give the model, and the same class verifies the response. Lesson 6 builds on this.

Async, and why it matters here

LLM calls take seconds and are almost entirely waiting on the network. Doing them one after another wastes that time; doing them concurrently is often a 10x speed-up on batch work.

import asyncio
from anthropic import AsyncAnthropic

client = AsyncAnthropic()

async def summarise(text: str) -> str:
    response = await client.messages.create(
        model="claude-sonnet-5",
        max_tokens=1000,
        messages=[{"role": "user", "content": f"Summarise in one sentence:\n\n{text}"}],
    )
    return next(b.text for b in response.content if b.type == "text")

async def main(documents: list[str]) -> list[str]:
    return await asyncio.gather(*(summarise(d) for d in documents))

asyncio.run(main(docs))

Rules of thumb, coming from JavaScript: async def is async function, await is the same, asyncio.gather is Promise.all. The difference is that Python does not run an event loop by default — asyncio.run starts one, and a blocking call (time.sleep, requests.get, a synchronous database driver) inside async code stalls everything.

# bound the concurrency, or you will hit rate limits and 429s
semaphore = asyncio.Semaphore(5)

async def limited(text: str) -> str:
    async with semaphore:
        return await summarise(text)

    r.raise_for_status()
    items = r.json()

httpx is the modern choice because it does both sync and async; requests is the classic sync-only one you will meet in older code.

Notebooks are for exploration, not for products Jupyter is genuinely useful for poking at data and trying a prompt. But hidden execution order and un-testable cells make it a bad home for anything that runs in production. Prototype in a notebook, then move the code into modules with tests.

# tests/test_chunking.py
def test_chunks_overlap():
    chunks = chunk_text("a" * 2500, size=1000, overlap=100)
    assert len(chunks) == 3
    assert chunks[0][-100:] == chunks[1][:100]

Things that will bite you

  • Mutable default arguments. def f(items=[]) shares one list across all calls. Use None and create inside.
  • Late-binding closures in loops — capture with a default argument or functools.partial.
  • Encoding. Always pass encoding="utf-8" when reading and writing files; on Windows the default is not UTF-8 and your PDFs will mangle.
  • Blocking calls in async code. Use asyncio.to_thread(...) to push a synchronous library off the event loop.
  • Floating point. Same as everywhere: never use it for money.
Practice
  1. Create a project with uv, add anthropic and pydantic, and load an API key from .env without hard-coding it.
  2. Write chunk_text(text, size, overlap) -> list[str] with type hints and a pytest test. You will reuse it in lesson 10.
  3. Define a Pydantic model for a support ticket (id, subject, body, priority enum, created date) and print its JSON schema.
  4. Write an async function that summarises 10 strings concurrently with a semaphore of 3, and time it against the sequential version.
  5. Set up ruff and pytest, and make both pass on your project.
