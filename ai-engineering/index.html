AI Engineering

Building products on top of models that already exist. Not training them — integrating them, grounding them in your data, giving them tools, and making the result reliable enough to ship.

Who this is for

Developers. If you already build software — frontend, backend, either — you have most of what this job needs. AI engineering is mostly ordinary engineering (APIs, data pipelines, latency, cost, tests) applied to a component that is non-deterministic. That last part is what these lessons are really about.

You do not need heavy maths. You need to understand embeddings well enough to reason about retrieval, and enough statistics to read an evaluation table honestly. That is a different bar from ML engineering, where you would be training and optimising models.

Code in this course

Examples are Python with the official Anthropic SDK, because a course needs one concrete API and this one is current. Every concept — messages, streaming, tool calling, structured output, caching — has a direct equivalent at OpenAI, Google and the open-model servers; the shapes differ, the ideas do not. Lesson 4 covers what is portable and what is not.

Model APIs drift faster than tutorials Parameters get removed, model IDs change, and last year's blog post confidently teaches something that now returns a 400. Treat every snippet you find online — including these — as a starting point, and check the provider's own reference. Building the habit of reading primary documentation is itself part of this job.

What "job-ready" means here

  • You can take a business problem and say honestly whether an LLM is the right tool.
  • You can build a retrieval pipeline whose answers cite their sources and whose retrieval quality you have measured — not guessed.
  • You can give a model tools and keep the loop bounded, observable and safe.
  • You can put a number on quality, latency and cost, and improve one without silently wrecking the others.
  • You have two or three finished projects someone can run, and you can explain every design decision in them.

Prerequisites

Comfortable in at least one programming language, able to use git and the terminal, and able to read HTTP and JSON. Python is taught in lesson 2 at the level this work requires. Docker and SQL show up later; the Spring course covers those ideas from the backend side if you want them first.
