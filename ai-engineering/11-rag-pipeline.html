Building a RAG pipeline

Retrieval-augmented generation: search your data, put the results in the prompt, answer from them, and cite the sources. The most requested feature in the industry, and the one most often built badly.

Why RAG rather than a bigger model or fine-tuning

RAGFine-tuningLong context (paste everything)
Teaches factsYes, at query timeUnreliablyYes
UpdatesRe-index a document, secondsRetrainFree
Cost per queryLow — only relevant chunksLowHigh — you pay for everything, every time
CitationsNaturalNoPossible but weak
Access controlFilter at retrievalImpossibleImpossible
Scale of corpusUnbounded—Context window

Fine-tuning teaches behaviour and format; retrieval supplies knowledge. When someone says "we fine-tuned it on our documentation and it still gets facts wrong", this is why (lesson 19).

The pipeline

question
   → (optional) rewrite / expand the query
   → retrieve top-k chunks   (vector + keyword, filtered by permissions)
   → (optional) rerank
   → assemble prompt with numbered sources
   → generate answer with citations
   → validate citations, return answer + sources

A complete implementation

from dataclasses import dataclass
import anthropic

client = anthropic.Anthropic()

@dataclass
class Source:
    id: int                 # 1-based index shown to the model
    chunk_id: str
    title: str
    url: str | None
    page: int | None
    text: str


def retrieve(question: str, tenant: str, k: int = 8) -> list[Source]:
    vector = embed_query(question)
    rows = store.search(vector, tenant=tenant, k=k)      # lesson 9
    return [
        Source(i, r.chunk_id, r.title, r.url, r.page, r.content)
        for i, r in enumerate(rows, start=1)
    ]


def format_sources(sources: list[Source]) -> str:
    return "\n\n".join(
        f'<source id="{s.id}" title="{s.title}" page="{s.page}">\n{s.text}\n</source>'
        for s in sources
    )


SYSTEM = """You answer questions using only the sources provided.

Rules:
- Use only information from the sources. Do not use prior knowledge.
- Cite every factual claim with the source id in square brackets, like [2].
  A sentence may cite several sources: [1][3].
- If the sources do not contain the answer, reply exactly:
  "I could not find this in the available documents."
  Do not guess, and do not offer general advice instead.
- If sources disagree, say so and cite both.
- Answer in the language of the question. Be concise: at most 150 words unless
  the question requires a list.
"""


def answer(question: str, tenant: str) -> dict:
    sources = retrieve(question, tenant)
    if not sources:
        return {"answer": "I could not find this in the available documents.", "sources": []}

    response = client.messages.create(
        model="claude-opus-5",
        max_tokens=2000,
        system=SYSTEM,
        messages=[{
            "role": "user",
            "content": (
                f"<sources>\n{format_sources(sources)}\n</sources>\n\n"
                f"<question>\n{question}\n</question>"
            ),
        }],
    )

    text = "".join(b.text for b in response.content if b.type == "text")
    cited = extract_citation_ids(text)                     # e.g. {1, 3}
    used = [s for s in sources if s.id in cited]

    return {
        "answer": text,
        "sources": [
            {"id": s.id, "title": s.title, "url": s.url, "page": s.page} for s in used
        ],
        "usage": {"input": response.usage.input_tokens, "output": response.usage.output_tokens},
    }
import re

def extract_citation_ids(text: str) -> set[int]:
    return {int(n) for n in re.findall(r"\[(\d+)\]", text)}

Citations are the product

Without citations, a RAG answer is an unverifiable claim, and users are right not to trust it. With them, a user can check in two seconds — and your support team can debug a bad answer by looking at what was retrieved.

def validate_citations(text: str, sources: list[Source]) -> list[str]:
    problems = []
    valid_ids = {s.id for s in sources}
    cited = extract_citation_ids(text)

    for bad in cited - valid_ids:
        problems.append(f"cites non-existent source [{bad}]")     # hallucinated citation

    sentences = [s for s in re.split(r"(?<=[.!?])\s+", text) if len(s) > 40]
    uncited = [s for s in sentences if not re.search(r"\[\d+\]", s)]
    if len(uncited) > len(sentences) / 2:
        problems.append("most claims are uncited")
    return problems

A stricter check, worth it in high-stakes domains: for each cited sentence, verify with a cheap model call that the cited chunk actually supports it. That is a small "faithfulness" evaluator, and lesson 16 turns it into a metric you track.

The failure modes, and where they come from

SymptomWhere the bug is
"I could not find this" for something clearly in the docsRetrieval: bad chunking, wrong embedding model, missing hybrid search, or an over-restrictive filter
Answer is right but incompletek too small, or the answer spans chunks that were split badly
Answer contains facts not in the sourcesPrompt not strict enough, or the model is falling back on training knowledge — tighten the instruction and check faithfulness
Citations point at the wrong sourceSource ids not stable between formatting and validation
Confidently wrong from an outdated documentIngestion: deletions and updates are not reaching the index
SlowToo many chunks, reranking every query, no caching
Expensivek too large; long chunks; resending the whole context on every conversational turn
Debug retrieval before you touch the prompt When an answer is wrong, first print the retrieved chunks. If the answer is not in them, the generation prompt is irrelevant — you have a retrieval problem, and lesson 12 is the fix. Most teams waste days tuning prompts to compensate for retrieval they never inspected.

Conversational RAG

Follow-up questions break naive retrieval, because "and what about for contractors?" embeds to nothing useful. Rewrite the question into a standalone one before retrieving:

REWRITE = """Given the conversation and a follow-up question, rewrite the follow-up
as a standalone question that makes sense without the conversation.
Return only the rewritten question."""

def standalone_question(history: list[dict], question: str) -> str:
    if not history:
        return question
    transcript = "\n".join(f"{m['role']}: {m['content']}" for m in history[-6:])
    return cheap_model(f"{REWRITE}\n\n<conversation>\n{transcript}\n</conversation>\n\n"
                       f"<follow_up>{question}</follow_up>")

Then retrieve with the rewritten question, but answer with the full conversation in context. Also decide whether a turn needs retrieval at all — "thanks!" and "make that shorter" do not, and a cheap classifier in front saves both latency and money.

Cost and latency shape

per question:
  1 embedding call         ~5 ms,   negligible cost
  1 vector query           ~10 ms
  (optional) rerank        ~100-300 ms
  1 generation call        1-5 s,   dominated by output tokens
                           input ≈ system + k chunks (k=8 × 700 tokens ≈ 5,600)

Levers, in the order to reach for them: cache the system prompt; keep k as small as quality allows; use a cheaper model for rewriting and routing; stream the answer so perceived latency drops; and cache answers for repeated questions (semantic caching, lesson 17).

Beyond the basic loop

  • Retrieve small, present large. Embed small precise chunks, but send the model the surrounding section — index the sentence, return the paragraph.
  • Parent-document retrieval is the same idea formalised: children for matching, parents for context.
  • Metadata pre-filtering beats post-filtering: apply date, type and permission filters inside the query.
  • Multi-index routing — separate indexes for product docs, contracts and tickets, with a cheap classifier picking which to search.
  • Agentic RAG — give the model a search tool instead of a fixed pipeline, so it can search several times and refine. More powerful, more expensive, harder to evaluate. Start fixed, move to agentic only when you have measured the fixed version failing (lesson 13).

Permissions

Retrieval is an access-control surface Whatever a user can retrieve, they can read — the model will happily quote it. Filter by the user's permissions inside the retrieval query, using the identity from your auth layer, never a value the client sent. Test it: log in as a low-privilege user and try to extract a document you should not see.

Showing it in the UI

  • Stream the answer.
  • Render citations as links to the source, ideally deep-linked to the page or section.
  • Show the sources that were used, and make them expandable to the actual chunk.
  • Say clearly when nothing was found rather than filling the space.
  • Offer thumbs up/down and store it with the question and the retrieved ids — that is your future eval set, collected for free.
Practice
  1. Build the full pipeline over 20–50 real documents you care about: ingest, embed, store, retrieve, answer with citations.
  2. Write 20 questions you know the answers to, run them all, and score each answer yourself as correct / incomplete / wrong. This is your first eval set.
  3. For every wrong answer, print the retrieved chunks and classify the failure as retrieval or generation. Count each.
  4. Implement citation validation and catch at least one hallucinated citation.
  5. Add question rewriting and test a three-turn conversation with pronouns and ellipsis.
  6. Ask a question the documents genuinely do not answer, and confirm you get the refusal rather than invention.
